AI Virtual Clinic — RuralAICare

AI-assisted triage for rural health workers. The AI organizes and prioritizes — a doctor makes every clinical decision.

🔗 Live app: ruralaicare.lovable.app 🛠️ Built with Lovable

What this is

Millions of rural health centres have a trained health worker but no doctor on site every day. RuralAICare is a web app that lets that health worker record a patient's symptoms and vitals, get an AI-assisted risk-triage assessment in seconds, and route the case to a remote doctor for review — before anything is ever finalized.

The core design rule, enforced end-to-end: AI suggests, it never decides. Every AI output is clearly labeled "pending doctor review," and no assessment is marked final in the database until a doctor approves, modifies, or overrides it.

Why it matters
A villager with fever, weakness, or a minor injury may be hours from the nearest hospital.
A health worker can take vitals and give first aid, but can't provide a full medical consultation.
RuralAICare closes that gap: structured intake → deterministic safety-critical triage → doctor sign-off → first-aid guidance or hospital referral.
Key features
New Patient Intake — symptoms, duration, history, vitals (temp, BP, pulse, SpO₂), and optional photo upload (wound or prescription), captured as plain text/numbers for a multilingual, low-friction form.
AI-assisted triage — a structuring + reasoning pipeline turns raw intake into a structured summary and a cautiously-worded preliminary assessment (never phrased as a diagnosis).
Deterministic risk scoring — the RED / YELLOW / GREEN risk tier is decided by hardcoded clinical rules, not by the LLM, so emergency detection is transparent, auditable, and doesn't depend on model behavior.
Explainability strip — every risk tier shows exactly which rule(s) fired (e.g. "SpO₂ 90% — below safe threshold").
AI Suggestion vs. Doctor Decision split — a two-panel review screen makes the safety boundary visually unmistakable: AI output on one side, the doctor's Approve / Modify / Override decision on the other.
Protocol-based first aid — for low-risk (GREEN) cases only, first-aid steps come from a fixed, pre-written set of protocols in the database — never freely generated by the LLM.
Drug-safety checks — OTC medicine suggestions are cross-checked against the OpenFDA drug label API for contraindications and age warnings before being shown.
Hard stop on emergencies — RED-tier cases skip first-aid and drug suggestions entirely and show only an immediate referral message.
Patient history — a searchable, filterable log of past visits with risk tier and review status at a glance.
Multilingual support — patient-facing flows support multiple languages so care isn't limited by the health worker's or patient's primary language.
How triage works
Patient intake (text/numbers)
        │
        ▼
1. Structuring   — extract structured JSON from raw intake (symptoms, vitals, history, language)
        │
        ▼
2. Reasoning     — draft a cautious preliminary assessment (never a diagnosis)
        │
        ▼
3. Risk scoring  — deterministic rules engine assigns RED / YELLOW / GREEN + reasons
        │
        ├── RED    → hard stop: referral message only, no first-aid/drug content
        │
        ├── YELLOW → remote doctor consult recommended
        │
        └── GREEN  → protocol-based first aid + OTC drug-safety check
        │
        ▼
4. Doctor review — Approve / Modify / Override; nothing is finalized without this step
Tech stack
Layer	Technology
Frontend	React 19, TanStack Start / Router, Vite, Tailwind CSS v4
UI components	Radix UI primitives + shadcn-style components, Lucide icons
Forms & validation	React Hook Form + Zod
Data fetching	TanStack Query
Backend	Supabase (Postgres, Auth, Edge Functions)
AI / LLM	Google Gemini (gemini-2.5-flash) — structuring, reasoning, and multimodal image analysis
Drug safety data	OpenFDA drug label API
Package manager	Bun
Data model (Supabase)
patients — id, name, age, preferred_language, created_at
visits — id, patient_id, symptoms_text, duration, history_text, vitals (jsonb), image_url, structured_summary (jsonb), preliminary_assessment, risk_tier, triggering_rules (jsonb), protocol_text, drug_safety_info (jsonb), status, doctor_decision, doctor_notes, created_at
first_aid_protocols — id, condition_name, protocol_text

All AI triage logic runs server-side in a Supabase Edge Function; the Gemini API key is stored as a Supabase secret and is never exposed to the client.

Getting started

Requirements: Bun (or Node.js + npm), a Supabase project, and a Gemini API key.

bash
git clone https://github.com/pashajamal/ruralaicare.git
cd ruralaicare
bun install        # or: npm i
cp .env.example .env   # fill in your Supabase and Gemini credentials
bun run dev         # or: npm run dev

Set GEMINI_API_KEY as a Supabase secret for the edge functions — do not put it in client-side environment variables.

Project status

This project was scaffolded and is actively developed with Lovable; every change made in the Lovable editor syncs directly to this repository. It started as a focused MVP (Intake → AI Review → History) and is expanding toward a fuller clinic workflow (patient queue, live consultations, follow-up tracking, referrals, medicine inventory).

⚠️ Safety note: This is a prototype / hackathon-stage project. It is not a certified medical device and is not intended to replace professional medical judgment. Every AI-assisted output requires human clinical review before it reaches a patient.
